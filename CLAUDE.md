# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**super-train** — a single-congregation (single-tenant) PWA that helps the territory servant **manage territory assignments** and **locate himself inside a territory** on a live map. The core pain it solves is field navigation ("não me perco no território").

Design and plan docs live in `docs/`:
- `docs/superpowers/specs/2026-07-02-super-train-mvp-design.md` — the approved design
- `docs/superpowers/plans/2026-07-02-super-train-mvp.md` — the implementation plan
- `docs/design/super-train.excalidraw` — data model + architecture diagram

## Commands

- **Dev server:** `npm run dev` (localhost, fixed port 3000 via `strictPort`).
- **Phone (real GPS):** `npm run celular` — LAN, **fixed port 3001**, HTTPS (self-signed via `@vitejs/plugin-basic-ssl`), which the browser requires to grant geolocation off-localhost. Runs alongside `npm run dev` (3000) instead of fighting it for the port. The phone opens `https://<ip-da-máquina>:3001` and has to accept the self-signed certificate once. The Mapbox token's URL allowlist must include that host, or the map comes up blank.
- **Build (typecheck + bundle):** `npm run build` (`tsc -b && vite build`).
- **Tests:** `npm run test` (Vitest, run mode).
- **Single test file:** `npx vitest run src/lib/territorios.test.ts`
- **Single test by name:** `npx vitest run -t "statusTerritorio"`
- **Lint:** `npm run lint` (oxlint).

## Architecture

React 19 + TypeScript + Vite SPA (PWA via `vite-plugin-pwa`) talking **directly** to Supabase — there is no backend server. Access control is enforced by Postgres RLS, not application code.

- **`src/lib/`** — the only place that touches Supabase. `supabase.ts` is the client singleton (reads `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY`). `types.ts` holds the domain types. `territorios.ts` / `publicadores.ts` / `designacoes.ts` / `saidas.ts` / `quadras.ts` / `rodadas.ts` are the typed data layer; UI never calls `supabase` directly. `statusTerritorio()` in `territorios.ts` and `progressoDe()` in `quadras.ts` are pure functions — territory state and progress are **derived**, never stored. `relatorio.ts` holds `folhaDoMes()`, the pure shaping of the monthly report — it composes `relatorioDoMes` + `passagensDoMes` + `campanhas` into the `Folha` the PDF draws, so all formatting decisions are testable without a renderer. `escala.ts` does the same for the Calendário's `Escala`, and additionally picks the typographic tier: `patamarDe(semanas, densidade)` is a lookup table keyed by how many weeks the grid spans and the busiest single day, because a calendar cell has a fixed height budget and Sundays run two saídas. `utils.ts` exports the shadcn `cn()` helper (clsx + tailwind-merge).
- **PostgREST caps every response** at the project's `max-rows` (1000 by default), silently and without an error. `quadra_feita` and `ponto_parada` are the tables that grow without bound, so `listMarcas()` / `listParadas()` page through them with `todasAsLinhas()` (`supabase.ts`) instead of a bare `select`. A truncated read here would make the report claim territories were never worked.
- **`src/auth/`** — single-user gate. `useSession` tracks the Supabase session; `App` renders `<Login>` until authenticated. RLS: `authenticated` = full access, `anon` = none.
- **`src/map/`** — `BaseMap` wraps Mapbox GL (`react-map-gl@8`, imported from **`react-map-gl/mapbox`**); `showLocation` mounts the `GeolocateControl` for the live "you are here". `TerritorioPolygon` renders **one feature per quadra** (so a tap can tell which quadra was hit), painted by `EstadoQuadra` (`feita` / `outra` / `falta`); `onQuadraClick` makes it interactive.
- **`src/screens/`** — `Cadastro` (draw polygon with `@mapbox/mapbox-gl-draw`, read via `draw.*` events, save GeoJSON), `Gestao` (status list + progresso `5/8` + publicadores + designar/devolver + nova rodada + excluir território), `Campo` (boundary + live position + quadras feitas em verde), `Calendario` (monthly field-service roster, **exports a PDF** via `src/pdf/EscalaPdf.tsx`; `SaidaForm` is its day panel), `MarcarQuadras` (`/saida/:saidaId/territorio/:territorioId` — marca no mapa o que a saída fez naquele dia). `TerritorioGlyph` renders a território's boundary as a small normalized SVG "seal" — one path per quadra, painting the ones already done. `Relatorio` is the monthly report; its button **exports a PDF** (see `src/pdf/`), it does not print. Routes wired in `App.tsx` behind the auth gate.
- **`src/pdf/`** — the monthly report as a real document, built from data rather than from the DOM. `RelatorioPdf.tsx` draws a `Folha` (from `lib/relatorio.ts`) with `@react-pdf/renderer`: A4 portrait, a repeated header, "Página X de Y", `wrap={false}` per território so none is split across pages, and the rodadas on their own `<Page>` — a `break` inside the table page would drag the table's column band along with it. The screen keeps its collapsed `<details>`; only the export is new. **The whole module is loaded with a dynamic `import()`** from the button handler, and `vite.config.ts` keeps its chunks out of the PWA precache (`globIgnores`) — react-pdf is 1.4 MB and the report needs Supabase anyway, so precaching it would only bloat the install for field use.
- **`EscalaPdf.tsx`** draws the Calendário's month grid, A4 **landscape**, one page by construction. What blows the page is not font size but **line wrapping inside a ~110pt-wide cell** — `"Salão do Reino da Congregação Central"` takes two lines, the dirigente's name one more. `maxLines` does nothing in react-pdf 4.5.1, so the clamp is **data**: `Patamar` carries `letrasDoLocal` / `letrasDoDirigente` / `letrasDaObservacao` and `escalaDoMes` truncates. That is what makes the max cell height computable. `verificacao.test.tsx` renders real PDFs across four months — from quiet to a 6-week month with three saídas every single day — and asserts `paginas === 1`. When it aches, the ladder is: observação → territórios → type size. Never the ponto de encontro, which is the day's headline.
- **PDF fonts** (`src/pdf/fontes.ts`) — react-pdf's fontkit reads **WOFF but not WOFF2, and does not instance variable fonts**. Atkinson Hyperlegible Next/Mono ship from Google Fonts as variable TTF only, so the PDF uses the *static* `@fontsource/*` packages' `.woff` files (the `@fontsource-variable/*` ones still serve the screen). The italic face is registered too, and `EscalaPdf`'s `"tarde ·"` marker forces `fontStyle: normal` — nested inside the italic "a definir" text it would inherit italic and ask for a mono italic that does not exist. Pointing a `src` at the `.woff2` sitting next to it in the same directory fails only at generation time, with an opaque fontkit error — `verificacao.test.tsx` renders a real PDF and asserts the four embedded font names precisely to catch that.
- **`supabase/migrations/`** — the schema (`0001_init.sql`, `0002_calendario.sql`, `0003_quadras_feitas.sql`, `0004_rodadas.sql`). The Supabase MCP is **read-only**; schema changes are applied by a human running the SQL in the Supabase SQL Editor, then committed here.

## Code style

- **Do not write comments in code.** Code should be self-explanatory through clear naming. Only add a comment if the user explicitly asks for it.

## UI & styling

- **Tailwind CSS v4** via the `@tailwindcss/vite` plugin — no `tailwind.config.js`; all config lives in `src/index.css` using `@import "tailwindcss"`, `@theme`, and `@layer`. `tw-animate-css` provides animation utilities.
- **shadcn/ui** components in `src/components/ui/` (`components.json`: new-york style, `rsc: false`, lucide icons, Radix primitives via the `radix-ui` package). Add components with the shadcn CLI; they land here and use `cn()` from `@/lib/utils`.
- **Design tokens** in `src/index.css` — a jw.org-derived, desaturated palette (`--color-jwblue`, `--color-sage`, `--color-ink`, `--color-paper`, `--color-danger`, …) exposed as Tailwind color utilities via `@theme`, plus shadcn semantic tokens (`--primary`, `--destructive`, …) mapped onto that palette. Light-only (`color-scheme: light`). Theme color `#33507d` also drives the PWA manifest.
- **Toasts:** `sonner` — `<Toaster richColors position="top-center">` is mounted once in `main.tsx`.
- **Nothing prints through the browser any more** — both screens export a PDF. What is left of `@media print` exists only so an accidental `Ctrl+P` is not grotesque: it unlocks the shell and hides chrome. The app shell is `h-dvh` with an `overflow-y-auto` `<main>`, and a fixed-height ancestor with a scroll container makes the browser emit **only the first screenful** — that is what cut the old report off. Both nodes carry a `data-casca` attribute the print block resets to `height: auto` / `overflow: visible`. Target that attribute, not the Tailwind utility classes: those are generated, and a layout tweak would silently break it again.
- **Path alias:** `@` → `./src` (configured in both `vite.config.ts` and `tsconfig`).

## Domain rules that shape the schema

- **One open assignment per territory**, enforced by a partial unique index: `unique(territorio_id) where data_devolucao is null`. A publisher may hold many territories.
- **Derived state (never stored):** availability = `ativo` AND no open `designacao`; "last worked" = latest `data_devolucao`; assignment open = `data_devolucao is null`; **progress** = distinct `quadra_feita` rows whose saída is on/after the current round's `inicio`; the **current round** = the território's latest `rodada` row. The only stored admin flag is `territorio.ativo` ("don't assign for now").
- Territory boundaries are **GeoJSON in a `jsonb` column** — no PostGIS. Since `0003`, `limites` is a **`FeatureCollection` of Polygons, each carrying `properties.id`**: a quadra has a **stable identity** (the id `mapbox-gl-draw` already assigns), so a mark survives redrawing and reordering. `quadrasDe()` still reads legacy `Polygon` / `MultiPolygon` rows, giving them index-based ids.
- **Quadras feitas.** A mark is `quadra_feita(saida_id, territorio_id, quadra_id)` — no date column (it's the saída's) and no boolean (the row existing *is* the mark). Its composite FK to `saida_territorio` cascades: deleting a saída, or dropping a território from one, cleans the marks. Marking happens **only from a saída** (the roster is the complete record of field work), on the map, after the fact. A round is closed **by hand**; nothing auto-resets, and zeroing never deletes marks. An orphan mark (quadra erased from the drawing) simply stops counting.
- **Rodadas.** A round is a row: `rodada(territorio_id, inicio, nome)`, and the current cut is simply the latest one — there is no `progresso_desde` column (`0004` dropped it, so the cut has exactly one source of truth). Keeping the *history* is not a safety net, it is what stops the report from rewriting the past: `concluidoNoMes` asks "did a round close in this month?" via `fechamentosDe()`, which replays the marks span by span, so a território that finished on the 12th still counts for that month after a new round starts on the 18th. A **campaign** is not an object — it is N rounds sharing an `inicio` and a `nome` ("Convites do congresso"), created in one gesture; `campanhas()` regroups them for display. Normal rounds have a null `nome`. Three entry points, each cutting at the date its context already knows: per território on Gestão (today, at any progress), "Nova rodada em todos" (a date you pick), and the action on the "já foi feita" toast in `MarcarQuadras` (cuts at `saida.data`, so the saída being marked lands inside the new round). None is undoable — previous cut lines are not reconstructible from the marks alone, which is exactly why they are stored.
- **The Calendário grid shows only the displayed month.** `gradeDoMes` returns whole weeks, so the first and last rows borrow days from the neighbouring months; those cells render empty, without even a day number, and are not click targets. `listSaidas` is asked for the month's own range rather than the grid's, so a neighbouring saída never reaches the state to begin with.
- **`saida` (the calendar) is not `designacao`.** A `designacao` is custody of a territory ("território 6 is with Kleber until he returns it"); a `saida` is one scheduled field-service outing (date, período, meeting point, dirigente, 0..N territories via `saida_territorio`). A day holds **N saídas** — Sundays run two in the same morning from different meeting points — so there is deliberately no `unique(data, periodo)`. The dirigente is nullable ("a definir"). The two concepts never talk to each other; the only coupling is that `saida` FKs make `on delete restrict` fire for publishers/territories already on the roster.
- **Deleting a território** (`excluirTerritorio`) is blocked by the `designacao` FK: the DB raises Postgres error `23503` when any assignment references it, and the UI translates that into a "has assignments" message rather than deleting the history.

## Out of scope (deliberately deferred)

Addresses/"não bater" list, service groups, group-level assignment, publisher logins, offline tiles, territory `tipo`, assignment `observacao`, Supabase Storage. Don't add these without a new design pass.

## Secrets

`.env` (git-ignored) holds `SUPABASE_ACCESS_TOKEN` (admin/MCP — **never** `VITE_`-prefixed), `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_MAPBOX_TOKEN`. `.env.example` documents the shape. The Mapbox token should be URL-restricted in production; for LAN phone testing its allowlist must include the dev host.
